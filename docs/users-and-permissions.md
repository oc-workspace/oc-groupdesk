# 用户管理、GitHub登录与资源共享

## 首版流程

- 本地admin保留总管理员身份和密码登录。所有既有机器人及历史群、话题、人设初始归admin管理，不变更实际微信运行或群配置。
- 总管理员在“用户管理 → GitHub登录”配置站点专用OAuth App。回调URL为`https://groupdesk.rococo.dev/api/auth/github/callback`，主页URL为`https://groupdesk.rococo.dev/`。在GitHub Settings → Developer settings → OAuth Apps → New OAuth App创建，Client ID和Secret仅在站点表单填写，不发聊天或提交仓库。
- 用户选择“使用GitHub登录”，通过公开身份授权后创建普通账号。**默认先由总管理员审核**：首次登录只显示等待审核，不发站点业务会话；管理员在用户列表选择“通过 / 正常使用”并保存，用户重新登录才能进入。注册规则可由总管理员切换为直接普通账号，但两种规则均默认无创建权限、无机器人分配。
- 待审核登录页使用醒目的琥珀色状态卡，明确显示「注册申请已提交」「等待管理员审核」及审核通过后再次使用GitHub登录的下一步；提示持续保留。窄屏优先展示审核状态，管理员密码入口默认折叠。页面打开或点击「刷新审核状态」读取最新结果，无定时轮询；审核通过显示绿色「审核已通过」及GitHub登录入口，仍需GitHub登录后进入业务。仅凭网址中的pending不再声称仍待审核。
- 待审核OAuth回调为当前浏览器设置7天有效、加密且限用途的HttpOnly注册回执，只供读取该申请的最小审核状态，不是登录凭据，不返回身份/权限/业务数据。停用、删除、过期及密钥变更会按真实状态或需确认处理；旧版本等待页和其他浏览器没有回执时，提示「请重新确认审核状态」，需再用GitHub验证一次。启动新的GitHub登录、本地管理员登录和退出登录会清除旧回执，删除重注册不能复用旧用户ID的回执。
- 管理员进入「用户管理」后，待审核申请人数显示在高对比度提示卡中；待审核账号统一置顶、带待审核标签与高亮边框，「审核申请」为主按钮。按当前准入状态判定，包括删除后重新注册的账号；保存为通过或停用后自动退出待审核区。审核仍由管理员明确选择准入状态和权限后保存，列表手动刷新。
- 管理员按需分配机器人、勾选各业务权限。审批、权限、机器人归属和资源共享四项独立，不会在审核通过时自动开放。

## 权限与归属

角色仅super_admin/user，权限采用可扩展命名注册表（shared/user-permissions.ts）。普通用户只列出自己的机器人，手工修改X-GroupDesk-Bot、机器人URL或资源ID不能越权。机器人启用限制现为每用户一个活动账号，不同用户互不影响；授予bots.manage权限后，普通用户可以按接入向导启用、暂停自己的机器人。同一用户切换仍等待旧账号停止确认，管理员代操作也遵守目标所有人配额。详细步骤见[多机器人管理](multi-bot-management.md)。

群归属于微信机器人；管理员分配机器人即授予访问该账号群及其业务数据的权限。总管理员能查看所有微信号、群及其创建归属，新增群/话题/人设记录实际操作者。历史资料缺少独立作者字段时由原admin账号托管，不能据此推断资料中发言人的作者身份。更改机器人所有人不会改写既有资源创建者；必须先暂停并确认停止，不能在等待切换时转移，原所有人的登录/读取确认会清除。

权限包括机器人创建/管理、群管理/接入、话题创建、人设制作、模型Key管理、知识库、互动、总结、讨论分析和成员授权。未授权的写操作由后端拒绝；只隐藏按钮不是权限控制。用户停用或权限/角色修改会撤销其会话，后续请求即时受新设置约束。至少保留一名有效总管理员。

## 总管理员删除站点账号（2026-11-08）

「用户管理 → 用户与权限」每行提供「删除站点账号」，与停用分开：停用可重新启用；删除后列表移除且不提供界面恢复。弹窗展示影响、名下机器人/Key与阻止原因，需要完整输入GitHub登录名（本地账号输入用户名）确认，并选择删除原因。只有仍然有效的总管理员可操作，不能删除当前登录账号，必须保留至少一名有效总管理员；删除接口事务内再次核对角色、版本和账号。

若用户仍拥有未删除的机器人（包括归档状态），先在机器人管理明确删除或转移归属；若仍有未归档Key，先在API Key管理归档。有在途模型调用/待计量记录时也禁止删除。不会自动将私人资源或Key转给管理员，不自动删除机器人、微信、真实群或Docker。

删除立即撤销登录会话、收到的公用Key授权和待审批申请，清除业务权限。已归档Key保持停用，原所有人UUID、加密密钥及历史账单保留；其他人包括总管理员仍只能看到尾号，不能借删除取得完整Key。既有素材、积分、创建者记录和共享资源保留，作者及用量页标明已删除账号。

同一GitHub数字身份再次登录会生成**全新用户UUID**，按站点当前规则重新注册（默认待审核），默认无权限、无机器人或旧Key/授权，不继承旧私有资源和指定用户共享。旧审核/启用接口不能恢复已删除UUID；可据此测试重复注册/审核。029控制库迁移保留历史身份但只对未删除身份保证唯一；业务库不复制控制列。机器人创建、归属、Key新增/启用/分配与账号删除协调加锁，避免并发产生悬空归属或重新授权。

## 删除原因与独占数据彻底清理（2026-11-08）

站点账号、微信登记、群配置删除均必选原因：测试号、违规、重复登记、不再使用、其他；支持500字补充说明，“其他”必须填写。后端校验，不凭隐藏按钮；历史记录未填写时标明“历史未填写”，不补造原因。原因代码、当时标签、补充说明、操作者、时间及对象名称写入审计；群删除同时在控制面保留精简事件，不随独立业务库清除丢失。

入口为「用户管理 → 已删除账号与数据清理」：最近100个已删除账号显示原因、执行进度和逐项保留原因，另有最近150条删除/清理审计。点击「预览独占数据清理」，列明将清理和保留项目；重新选择本次清理原因、输入账号确认后排队。后台worker再次核验再执行，页面手动刷新，无自动轮询，不在普通删除时偷偷物理清除。

可清理的项目是该已删除账号仍独占的、已删除且规范绑定的独立机器人数据库、受限数据库角色、`DATA_DIR/bots/<精确UUID>`资料目录，以及已停用归档的私人Key密文。数据库名/角色/目录必须逐一匹配该机器人UUID；拒绝符号链接和不可信路径、错误数据库所有人、活跃凭据、在途模型/后台任务。包含共享话题/人设或其他用户创建的群/话题/人设时，**整套业务空间保留**，不自动分拆或转给管理员。原RyuBuddy兼容库与控制库共用，不能在此物理清理。

Key清理保留所有人、尾号、价格、模型与账本，密文不可再展开、替换或启用；公用Key及其他用户资源不随私人账号清理。真实消费、未知金额、积分账本留存在尚需保留的业务空间；**被确认清除的独占业务库内素材、生成任务和娱乐积分明细会随库移除**，不再宣称这部分仍保留。API计费账本独立保留。精简账号/机器人和删除审计记录不擦除。

任务与逐项阶段持久化，重复工作进程只有一个能执行；中断后可续做已确认步骤，失败显示进度并可重新预览重试，不猜未核验的缺失库可以删文件。恢复备份会取消自动续跑的清理任务，要求管理员重新确认。微信登录目录、Docker栈和既有运维备份单独管理，本功能不删除这些；不承诺擦除历史备份中的副本。

## 资源共享

“资源共享”列出话题和人设及创建者；总管理员可设置：

- 私有：仅创建者和总管理员。
- 通用：所有可登录用户可访问。
- 指定用户：创建者、总管理员及所选用户可访问。

普通用户查看可访问资源时，不返回源机器人的微信号、群或账号名称。跨机器人使用需明确“复制到我的机器人”，生成独立私有副本。话题复制规则；人设只复制已发布SKILL文本，作为未发布草稿，需人工发布后应用。**不复制聊天素材、数据集、模型Key、群绑定或私有制作溯源。**共享人设的直接只读查看也不返回作者未发布草稿或任务输入。原始Skill包含制作溯源，仅作者/总管理员可导出；普通用户先复制独立稿。

撤销共享立即禁止后续访问和复制；用户之前另存的独立副本不会被远程覆盖或删除。共享作者修改不会静默改变其他机器人的副本或正在使用的人设版本。

## 登录安全与迁移

022_users_bot_control.sql仅控制库执行，新增角色/状态/权限、GitHub身份、机器人所有人及加密OAuth配置；023_resource_owners.sql为各业务库添加作者和共享范围，不更改群revision、话题内容或已发布Skill。GitHub使用state绑定浏览器、10分钟一次性授权状态与PKCE S256；按不可变GitHub数字ID识别，不能凭登录名或邮箱合并进admin。仅请求公开身份，不申请仓库权限；访问令牌仅登录瞬时使用，不入库。Client Secret和PKCE verifier以现有控制面主密钥AES-GCM加密存储。

GitHub凭据未配置或未启用时，入口不会出现，本地admin登录持续可用。生产真实GitHub登录需管理员完成OAuth App配置后验收；模拟授权测试不能替代这一步。控制表沿用managed_命名，不向机器人业务数据库角色授权。运行端配置剔除管理侧作者/共享字段，保持原有机器人契约。

运行环境另设总管理员入口[运行环境与备份](runtime-maintenance.md)，只支持已删除独立机器人；旧目录和备份只读。数据库清理与运行目录清理分别确认，删除部分记录不保证立刻缩小PostgreSQL文件，整库DROP通常释放对应文件。

机器人彻底清理现有独立入口，不再要求先删除所有人账号；用户的Key、其他机器人和公用授权保留。两种删除、旧共用库边界及已删除列表见[多机器人管理](multi-bot-management.md)。
