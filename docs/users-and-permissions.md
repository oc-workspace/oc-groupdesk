# 用户管理、GitHub登录与资源共享

## 首版流程

- 本地admin保留总管理员身份和密码登录。所有既有机器人及历史群、话题、人设初始归admin管理，不变更实际微信运行或群配置。
- 总管理员在“用户管理 → GitHub登录”配置站点专用OAuth App。回调URL为`https://groupdesk.rococo.dev/api/auth/github/callback`，主页URL为`https://groupdesk.rococo.dev/`。在GitHub Settings → Developer settings → OAuth Apps → New OAuth App创建，Client ID和Secret仅在站点表单填写，不发聊天或提交仓库。
- 用户选择“使用GitHub登录”，通过公开身份授权后创建普通账号。**默认先由总管理员审核**：首次登录只显示等待审核，不发站点业务会话；管理员在用户列表选择“通过 / 正常使用”并保存，用户重新登录才能进入。注册规则可由总管理员切换为直接普通账号，但两种规则均默认无创建权限、无机器人分配。
- 管理员按需分配机器人、勾选各业务权限。审批、权限、机器人归属和资源共享四项独立，不会在审核通过时自动开放。

## 权限与归属

角色仅super_admin/user，权限采用可扩展命名注册表（shared/user-permissions.ts）。普通用户只列出自己的机器人，手工修改X-GroupDesk-Bot、机器人URL或资源ID不能越权。机器人激活切换目前仍为全站互斥操作，仅总管理员执行；普通用户可在授予权限后维护自己的配置或暂停自己的机器人。

群归属于微信机器人；管理员分配机器人即授予访问该账号群及其业务数据的权限。总管理员能查看所有微信号、群及其创建归属，新增群/话题/人设记录实际操作者。历史资料缺少独立作者字段时由原admin账号托管，不能据此推断资料中发言人的作者身份。更改机器人所有人不会改写既有资源创建者。

权限包括机器人创建/管理、群管理/接入、话题创建、人设制作、模型Key管理、知识库、互动、总结、讨论分析和成员授权。未授权的写操作由后端拒绝；只隐藏按钮不是权限控制。用户停用或权限/角色修改会撤销其会话，后续请求即时受新设置约束。至少保留一名有效总管理员。

## 资源共享

“资源共享”列出话题和人设及创建者；总管理员可设置：

- 私有：仅创建者和总管理员。
- 通用：所有可登录用户可访问。
- 指定用户：创建者、总管理员及所选用户可访问。

普通用户查看可访问资源时，不返回源机器人的微信号、群或账号名称。跨机器人使用需明确“复制到我的机器人”，生成独立私有副本。话题复制规则；人设只复制已发布SKILL文本，作为未发布草稿，需人工发布后应用。**不复制聊天素材、数据集、模型Key、群绑定或私有制作溯源。**共享人设的直接只读查看也不返回作者未发布草稿或任务输入。原始Skill包含制作溯源，仅作者/总管理员可导出；普通用户先复制独立稿。

撤销共享立即禁止后续访问和复制；用户之前另存的独立副本不会被远程覆盖或删除。共享作者修改不会静默改变其他机器人的副本或正在使用的人设版本。

## 登录安全与迁移

022_users_bot_control.sql仅控制库执行，新增角色/状态/权限、GitHub身份、机器人所有人及加密OAuth配置；023_resource_owners.sql为各业务库添加作者和共享范围，不更改群revision、话题内容或已发布Skill。GitHub使用state绑定浏览器、10分钟一次性授权状态与PKCE S256；按不可变GitHub数字ID识别，不能凭登录名或邮箱合并进admin。仅请求公开身份，不申请仓库权限；访问令牌仅登录瞬时使用，不入库。Client Secret和PKCE verifier以现有控制面主密钥AES-GCM加密存储。

GitHub凭据未配置或未启用时，入口不会出现，本地admin登录持续可用。生产真实GitHub登录需管理员完成OAuth App配置后验收；模拟授权测试不能替代这一步。控制表沿用managed_命名，不向机器人业务数据库角色授权。运行端配置剔除管理侧作者/共享字段，保持原有机器人契约。
