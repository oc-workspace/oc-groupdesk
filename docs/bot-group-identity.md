# 每群机器人的称呼、自称与文字点名

## 使用入口

先选择左侧“当前管理的机器人”，进入“群管理”，选择目标群，在“参与、人设与语言范围”里的“本群机器人称呼与点名”设置：

1. **本群机器人称呼**：自我介绍或被问名字时使用，留空沿用机器人管理的名称。
2. **偏好的自称**：例如“小T”，留空按回复语言自然使用“我 / I / 私”。不强制每句话重复。
3. **本群单独设置文字点名名称**：每行一个字面名称，最多12个、每项80字符，英文忽略大小写，支持空格和标点，不填正则。显式空名单只接受适配器已验证的点名或引用标记；不勾选时沿用本群称呼、机器人管理名称和微信号。
4. 点“保存配置”，再手动刷新确认状态。机器人确认包含本群身份配置摘要，旧运行端不能确认新身份配置。

这些字段按机器人业务库和群ID双重隔离，不改微信实际昵称。当前Chatlog Reader数据库通道没有为普通@提供独立的已验证标记，普通“@昵称”也按文字名单识别，务必保留本群微信中的机器人实际昵称。引用机器人消息已有独立的同群原消息ID校验；其他适配器提供的可信点名标记也可不依赖文字名单。点名仍受群话题、语言、时效和预算约束。签到等互动的“必须点名”与指令去前缀使用同一名单，群互动页面的旧称呼输入已移除，避免出现两份配置。新群接入第2步也可设置；参考已有群时，称呼与名单会在表单里显示并可修改，AI推荐不覆盖这些人工设置。

## Persona 与身份

基础Persona和特色Skill只规定风格。机器人称呼/自称来自当前群可信配置，优先于Skill、合成示例、素材作者及历史回复；被点名时由自己回应，不把自己当作另一位群友。身份披露、语言与权限规则不变。

运行端原有“GT小跟班／小T／小GT”固定自称已移除。旧默认机器人配置的昵称与性格介绍中的固定自称也应改为其登记名称；引用自身旧回复时用“当前机器人”标识，不写死“小T”。本群身份指令在基础和特色Skill后注入，普通、简短、长文请求都覆盖。复制的独立GT基础包缺少原始参考文件时，只加载当前账号自己的独立SKILL正文，不读取其他账号目录。

现有人设维护使用 `scripts/maintain-bot-identity.ts`，经stdin传入机器人ID、各自点名名单和审查指纹：先查看计划，备份后按指纹执行。只修订当前草稿并基于**最新已发布内容**创建身份修订版本，不发布待审草稿或未发布人设；原历史版本及原始素材保持，固定历史版本不自动升级。跟随最新的绑定更新，固定版本仍受运行端身份边界约束。维护可重复执行，修订超出特色6000/组合30000限制时整空间回滚，不截断正文。

## 运行契约与发布

`bot_identity_contract_version=1`、`bot_identity`、`bot_identity_sha256` 和 `bot_name_instructions` 随本群配置、上下文与Persona预览返回，不包含Key。SHA256按 `[1,bot_id,group_id,display_name,self_reference,mention_names]` 的紧凑UTF-8 JSON计算。运行端验证账号、群、数据形状与摘要，配置不可用时按原有租约关闭；ACK携带 `bot_identity_version` 和匹配摘要。

文字点名在真实 `Policy.ingest` 中通过ContextVar绑定当前群，异常后也重置；补答识别和互动处理同样查该群。没有创建新的聊天扫描/轮询。账户默认文件仅用于旧契约兼容，显式空群名单不回退。

升级顺序：备份、空闲检查、暂停接收并确认无处理中发送、只重启MaiBot和桥接以加载模块；微信与Reader不重启、数据游标不重置。随后部署GroupDesk并修订各业务库，检查新摘要与真实ACK。暂停账号只预置模块/昵称，不启用、不跨账号复制队列或聊天。旧版网页保存时保留新身份字段；新版带 `name_policy_version=1` 时允许明确清除覆盖并恢复继承。

## AI身份与私人问题

每个群的“参与、人设与语言范围”中新增“AI身份与私人问题”设置：

- 不主动提及：日常不使用“作为AI助手”等自我介绍；直接问是否AI时简短如实说明。
- 首次交流或容易误解时主动说明：说明AI身份，但不每条回复重复。
- 私人问题回应：可选“礼貌带过，沿用当前persona风格”或“直接说明没有真人籍贯/生理性别”。

默认：不主动提及 + 礼貌带过。GT风格采用简短、机智、有分寸的接话；中性persona不继承GT示例。

“你从哪里来”“男的女的”是一般私人问题，可礼貌带过。在普通两种披露模式中，直接问“你是不是AI/机器人/真人”时如实说明；群成员已知情的Cosplay按下节规则处理。

这次调整技能与系统策略，没有微调或重新训练基础模型。知识库与用户聊天内容不能更改该群设置。服务端校验枚举，配置以群为单位保存、递增版本并等待机器人确认。

迁移仅为缺少identity字段的已有群补默认值并递增版本；重启不覆盖已有选择。可选字段扩展保持policy_contract_version=1兼容性。旧适配器不能应用新设置，部署时必须同步更新MaiBot绑定模块。

### 沉浸式Cosplay（roleplay）

用户已确认两个群的成员都知道机器人是AI角色。新增第三项“沉浸式Cosplay（群成员已知情）”，只用于这种明确知情的虚构互动。

角色内沿用当前Persona，保持设定；来历、性别或角色内“是不是机器人”的接梗不自动触发跳出角色。明确说“跳出角色”“OOC”或认真确认系统真实身份、对虚构性质真正困惑时，简短如实说明并尊重退出。不冒充GT真人，不把虚构背景用于现实事实或私有知识。

Cosplay模式的私人问题以角色设定为主，普通模式的私人问题下拉项暂时禁用，但保留原值，切回普通模式可继续使用。语言、话题、知识访问及预算限制不变。

这是新增可选项，不自动把现有两个群切换过去；选择后保存，待机器人确认该群新版本才生效。
