# Persona 工作室

「Persona 制作」管理任意数量的人设、素材和群配置。既有 GT 模式继续工作；导入制作模块不会自动替换群的人设。

## 素材与数据集

创建素材库后可直接导入 UTF-8 JSONL，无需先创建运行群。运行群关联可选；通用素材库同样支持个人与群像 Skill。每行至少包含 `id`、`group_id`、`sender_id`、Unix 秒数 `timestamp`；`authored_text` 是发送正文，`quoted_context` 和 `shared_content` 分开保存。首次导入记录文件中唯一的素材来源群 ID，后续不同的来源 ID 会令整次导入取消。素材来源 ID 与机器人传输绑定 ID 分开，不能用群列表序号代替微信历史中的群 ID。

按 `(素材库, 来源 id)` 对账。相同快照 SHA-256 重复导入直接复用；新快照统计新增、更新、重复记录。相同文字的不同发送记录仍保留，快照里没有出现的历史不会被删除。原文件、校验值和每次导入结果保留在私有数据目录与数据库中。

通用参考资料库支持 TXT、Markdown 和文字型 PDF。同名参考文件更新相同来源记录，旧原文件仍在导入历史中。单次最多 100 MB；不自动 OCR/语音转写。全群媒体记录不等于已提取媒体内容。

制作个人 Persona 时按真实发送者账号筛选；制作群像时可选多人或全部发送者，均可增加日期范围。空发送者列表代表全部发送者。不同账号的相同昵称不会合并，他人引用目标人物不算目标发言。新导入的匹配记录自动进入数据集。可浏览、检索、排除不适合归纳的记录，随时导出 JSONL。

## 生成和人工维护

创建 Persona，关联数据集，填写制作目标，并选择模型 Key/文字模型。同库重叠筛选先合并，再按素材库分层、库内按时间等距抽取最多500条可读正文、共10万字符；分析文档保留独立篇幅，不使用引用/分享作为本人正文。统计与排序在数据库完成，应用只接收有限样本；关键词匹配分批处理并保持别名语义。上传记录和最终选用样本数量分别显示。长正文可能截取，完整语料始终可另行导出。

「制作完整草稿」会先保存当前设置和人工编辑，再把冻结样本、目标和已有完整草稿发送给选定服务，可能计费。初始化占位模板不作为旧稿发送。只点「保存设置」不会生成内容；尚未完善的占位模板不能发布。它归纳 Skill，不训练或微调模型参数。模型目录可见不等于已验证调用成功。

任务保留制作时的筛选器、样本来源哈希和导入 ID，并将输入写入私有快照。生成期间若有人修改草稿，结果以“需人工合并”保留，不覆盖人工编辑；Key 已更换或停用则拒绝应用结果。任务超时不会自动重复计费请求，需人工重新生成。

Persona草稿请求最多等待240秒，低于后台任务300秒的过期检查，留出校验与保存时间；这与群聊Planner的按群超时独立。仅选用plain gemini-3.8-flash时请求LOW思考且隐藏思考文本，其他变体及协议保持原参数，输出上限不增加。

Persona 的创建、生成、人工修订、发布和 Skill 包导出都不要求关联运行群。只有需要机器人使用它时，才在「群人设配置」中选择应用。

SKILL.md 包含 name、description 和独立正文，可人工修饰。保存草稿、发布不可变版本、应用到群是三个动作。可把历史版本载入草稿继续维护，也可以让群重新选择旧版本。Skill 包提供 SKILL.md 与来源元数据，可导出 tar.gz。

## 给群配置人设

「群人设配置」单选一个基础 Persona，并可勾选最多五个特色 Skill。每项可固定发布版本或跟随最新发布；保存草稿不会影响群聊。旧群继续固定原版本，恢复内置后回到该群原先选择。组合、跟随、迁移与回退详见[基础与特色 Skill 组合](persona-composition.md)。

应用会递增群配置版本，机器人验证 Skill 版本和 SHA-256 后才确认。旧适配器不能确认带自定义 Persona 的群。语言、身份披露、知识权限、话题、频率与预算继续由群和现有强制门控控制，Persona 不授予新的工具或发送权限。

归档是可恢复的移除；被群使用或仍在生成的人设须先更换/解除绑定或完成任务。发布历史、素材不会因归档而清除。

确认和任务均只手动刷新，不设置浏览器轮询。「查看制作进度 / 载入结果」在没有未保存编辑时，直接将服务器的完整结果载入SKILL.md编辑框；有未保存编辑则只更新状态并保留本地内容。每次任务的完整结果另行保留，便于对照或显式采用。

## 本机微信更新

网页不能直接读取 Mac 微信数据库。现有本机采集项目的 `scripts/sync_persona_materials.py` 可只读导出完整新快照，并通过已配置 SSH 导入；素材按来源 ID 增量对账。实现副本位于 `integration/local-collector/`，依赖采集项目已有的 `wechat_summary_bridge.py` 和 `export_persona_messages.py`，不在服务器上运行。

```bash
python3.14 scripts/sync_persona_materials.py --group '群名' --collection <素材库UUID>
```

使用本机项目 .env 中的采集白名单和数据库配置，不输出密钥。`--export-only` 只存档；`--snapshot <已有快照目录>` 用于网络失败后重试，导入前后校验 SHA-256。新的完整快照不会覆盖旧目录。没有配置周期任务，也不触发微信群发送。

生产部署遵循既有开发仓库、隔离发布桥、PR 审阅合并和 Docker 脚本。Persona 原文件与任务输入位于 DATA_DIR/persona，在既有 files 备份范围内；数据库仍需连同外置模型加密主密钥一起备份。
