# 群聊话题、语言与 skill 管理

## 结构

采用一个通用 `skills/group-participation/SKILL.md`，配合数据库中的话题和群配置。话题是可编辑数据，不必每增加一个词就创建新 skill。群选择 persona，话题说明决定讨论内容，知识库提供可引用的私有资料。

| 位置 | 内容 | 维护方式 |
| --- | --- | --- |
| `skills/group-participation/` | 群权限、话题与语言的通用执行规则 | 代码发布 |
| `catalog/topics/<key>/` | 可复用初始话题、分语言词表、合成例句 | Git 版本管理 |
| `schemas/` | 话题和群策略的数据契约 | 随构建导出 |
| PostgreSQL `topics.policy` | 当前实际使用的关键词、组合、排除、承接与讨论深度 | 后台编辑 |
| PostgreSQL `groups.policy`、`group_topics` | 每群勾选、深度覆盖、参与程度、persona、语言 | 后台编辑 |
| 知识库及群关联 | 文档、资料来源与权限 | 后台编辑 |
| `integration/maibot/` | MaiBot 同步与执行适配 | 按部署基线应用 |

初始话题共11类：创业经营、AI产品与应用、商业合作与资源交流、语言学习、跨文化生活、计算机技术、网络技术、旅游见闻、游戏开发与游戏交流、3D建模、中国各地美食。中英文词条归于同一话题，不需要为英语复制整套规则。首次启动导入模板；以后重启不覆盖编辑，也不自动恢复删除的话题。

## 日常维护

1. 在“话题库”选择或新建话题，编辑说明、回复指导和讨论深度。
2. 展开识别规则，按语言增减词条。词条为普通文字，不执行正则或代码。词条的语言用于分类维护；识别不会因为该语言没有被选为回复语言而关闭。
3. 需要组合时，设置多个条件组：组内任一词命中即可，不同组必须同时满足。例如“food / soup / 汤”与“tasty / good / 鲜”组合。单独的泛词可以不列为直接命中。
4. 配置排除词及承接规则。承接必须已有同群同话题起点，默认最长180秒、最多间隔3条无关消息；承接不会延长起点寿命。明确换题取消旧起点。
5. 保存后用合成消息预览。预览只验证规则，不调用模型、不发送微信消息，也不承诺一定回复；真实参与仍受群配置、频率、额度和客户端状态限制。
6. 在“群管理”勾选话题，可只在该群覆盖某话题的讨论深度。需要不同词表时，复制为独立话题，再分别勾选；编辑共享话题会影响所有选中它的群。

模板导入默认只补缺失项。覆盖现有内容需明确选择，并检查版本冲突。不要用模板导入代替数据库备份。

## 每群的行为选择

- 话题范围“主动插话”：未点名按勾选话题及启用的基础问题/社交候选筛选，明确点名可回答其他一般问题。
- 话题范围“全部回复”：点名也受所选话题约束。私聊场景始终执行该范围。
- 安静：只响应点名。适中：普通插话额外要求本群至少180秒间隔。活跃：使用现有共享插话间隔和额度；不是每条必回。
- 基础问题、基础社交可独立关闭。点名优先、合并、队列、时效和全局 token 预算仍由现有机器人限流层执行。
- GT persona 使用机器人已有的私有 skill 挂载；中性 persona 不加载 GT 语料。真实人设资料不放公开仓库。

## 语言选择

- 跟随成员：按本轮语言自然回复；允许指定语言时尊重请求。
- 限定语言：只使用勾选的输出语言；输入是其他语言时使用回退语言。
- 固定语言：默认使用指定语言；是否允许成员请求其他已允许语言可单独选择。

词表语言和输出语言分别设置。模型生成时绑定语言规则，发送前阻止明显不符的文字；短句、人名、代码或相近拉丁语种无法保证完全自动判别，不为语言检测额外调用模型。

## 同步、权限和故障

保存后增加关联群 revision。适配器每30秒读取一次，应用并确认版本，后台才显示已应用。同步成功的配置租约75秒；同步失败、停用、权限撤销或版本变更均停止旧配置任务，发送前再次检查服务端版本。网络故障可能暂时影响机器人参与，这是避免使用已撤销权限的取舍。

后台新建群不会自动获得微信读取权限。必须先在可信适配器完成会话绑定和授权；专用令牌只访问被授权群。当前 UI 桥的昵称派生 ID 不能验证跨群身份，因此不自动开通私聊或成员核验。微信掉线、锁定或消息方向无法识别时，后台配置无法替代客户端恢复。

配置同步不上传微信群消息全文；仅当实际获准处理时，按群向运行接口发送裁剪后的本轮查询以检索授权资料。聊天仍按既有许可发送给已配置的模型服务。

## 验证与备份

使用 `npm run catalog:check`、`npm run build`、`npm test`、隔离 PostgreSQL 集成测试及无网络 MaiBot 测试。集成测试只运行专用临时数据库。禁止用真实群消息冒充预览测试。

运行数据通过 PostgreSQL 备份保存；Git 中模板不是数据库实时镜像。连接文件、专用令牌、真实群绑定、聊天和 GT 语料不提交 Git。生产发布、备份和恢复遵循项目 README。

## 用 Prompt 自动补齐话题

在「话题库 → 新建话题」或「编辑话题」顶部填写 Prompt，例如“我想增加一个关于美食的话题”，选择已有 API Key 与文字模型，点击「AI 帮我补齐话题」。也可以描述希望调整的范围，让 AI 参考当前草稿继续完善。

结果会填入下方名称、说明、回复规则、词条、组合、排除/承接和讨论深度。完成反馈提供「查看回复规则」「查看识别策略」按钮；可以继续修改。点击「保存话题」后才写入话题库，新的话题还需在群管理勾选启用。编辑已有话题保存后按原流程更新关联群的配置版本。

请求仅使用本次 Prompt 与当前话题草稿，不读取聊天素材；会调用所选服务并可能计费。生成失败或取消等待保留原内容。停止等待会中止上游请求，但服务可能已经开始处理。没有新增页面轮询。

话题生成沿用现有三种协议。对于已配置的 plain gemini-3.8-flash，使用 LOW 思考以减少等待或只有思考而无可用输出的情况，参考[Google 官方 generateContent 思考配置](https://ai.google.dev/gemini-api/docs/generate-content/thinking)。Persona 原有调用默认值保留。
