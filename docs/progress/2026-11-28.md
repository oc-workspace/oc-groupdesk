# 2026-11-28

## 范围与问题定位

用户在全新 Apple Silicon Mac 实机双击 `20261126-r1` 的 `GroupDesk.app` 首次初始化时，输入 16 位以上管理员密码后触发 `FileNotFoundError` 中止，且终端末尾仍打印“服务将在后台持续运行”造成误导。

根因定位：
- `distribution/manage-macos.py` 的 `initialize()` 在创建实例目录 `~/Library/Application Support/GroupDesk/default` 时仅调用 `root.mkdir(mode=0o700)`，未先创建缺失的父目录 `GroupDesk`；`distribution/manage.py` 存在相同隐患。
- `scripts/package-macos-native.py` 中 `GroupDesk.app` 启动脚本 `LAUNCHER_SCRIPT` 使用 `;` 串接末尾提示，导致 `init`/`up` 失败后仍输出“服务将在后台持续运行”。

## 修复内容与关键决策

- 在 `distribution/manage-macos.py` 和 `distribution/manage.py` 的 `initialize()` 中先执行 `root.parent.mkdir(parents=True, exist_ok=True)`，再保持 `root.mkdir(mode=0o700)`（不带 `exist_ok=True`，保留拒绝覆盖既有实例的原子保护）并显式 `root.chmod(0o700)`。
- 修改 `scripts/package-macos-native.py` 的 `LAUNCHER_SCRIPT`，用 `if ... && ... && ...; then ...; else ...; fi` 区分首次初始化/启动成功与失败提示。
- 更新 `distribution/BUILD-PROVENANCE.json` 的 `package_refresh_date` 为 `2026-11-28`（保持生产 PR166 提交 `39454151f08d7c94b6feadcbec9a3517aa0c4b93` 及修复文件 SHA-256 校验不变）。
- 在 `tests/test_standalone.py` 新增 3 项回归单测：macOS/Linux 缺失嵌套父目录自动创建与覆盖保护、以及 `GroupDesk.app` 启动器失败分支文案校验。
