# 运行环境、旧目录与备份管理

## 范围与入口

总管理员在「管理与设置 → 运行环境与备份」提交盘点、手动刷新任务与结果。普通用户没有入口和接口权限。rococo-root只盘点GroupDesk既有备份；rococo-root2盘点UUID独立机器人部署及明确列出的旧目录。安装或升级不会创建清理任务、移动现有数据或按保留天数自动删除。

当前允许处理**已删除登记、归档状态且凭据已撤销**的独立机器人；显式登记的RyuBuddy旧栈按本页末尾专用退役规则处理。运行中、暂停或仅归档的机器人不能直接执行主机清理。站点用户数据清理仍见[用户与权限](users-and-permissions.md)，与本模块分别确认。不能根据服务器备注或微信名猜目录归属。

## 手动操作顺序

1. 提交只读盘点，等待任务完成后手动刷新。显示主机余量、目录逻辑大小/估计占用、容器、共享引用、旧目录、备份及阻止原因。盘点只读文件元数据，不读聊天正文、密钥、env或备份内容；未知大小不当作0，不宣称备份完整性已验证。
2. 对已删除的独立机器人「预览清理」。盘点有效15分钟；核对UUID、运行实例、目录、容器和共享引用。勾选需要的资源：微信登录目录、Reader、MaiBot、桥接、身份/凭据、部署文件、容器/独立网络。部署文件必须连同容器选择。任意范围都会先停止这一机器人的整套运行栈及四个受支持的systemd实例，禁止自动重启，其他机器人不停止。
3. 选择原因（测试号、违规、重复、不再使用、其他；其他须说明）、输入完整微信号，确认「停止并暂存」。目录在同一数据根内原子移动至`.quarantine/<无横线UUID>/<任务UUID>/…`，保留容器和网络。建议保留0—30天，默认7天；**暂存不释放文件空间，到期只提示**。
4. 暂存后可另行确认「还原」或「永久清理」。还原拒绝覆盖原位置新数据，保留停用状态，不恢复已删除账号/登记、不自动启动。永久清理只能处理原暂存范围；提前执行需额外勾选确认。镜像、旧目录、既有备份始终保留，不调用Docker prune。

任务保留操作者、原因、说明、目标UUID、时间、状态与回执。尚未执行的任务可取消；失败任务可按原范围重试。执行器本地锁和逐项日志支持中断续作，重新验证许可、容器和目录身份，拒绝顺势扩大范围。操作完成仍需手动刷新。

## 避免误删其他机器人

控制面与主机各自验证：有效总管理员、登记版本/所有人、无预留计费/待切换/适配器凭据；固定UUID部署/持久化根、可信清单与运行实例、Compose项目/服务/工作目录、自有网络、所有容器（含停止的）的挂载引用。符号链接、硬链接、非允许挂载、目录内备份、未知服务/网络及其他容器引用均保留待核对。还原和清理核对暂存目录inode，拒绝替换后的目录。盘点有时间/条目预算，无法完整核验就标明未知并阻止该范围。

主机令牌只能领取自己主机的已审核任务，不能创建任务或传任意路径/命令；实际修改另需控制面再次校验并签发180秒HMAC许可，绑定任务、主机、机器人、计划、范围和租约。网页容器不挂Docker socket，不存SSH凭据。rococo-root在接口和本地主机同时禁止修改。

## 数据库与磁盘空间

| 操作 | 空间效果 |
|---|---|
| 删除账号/群登记或清除表中记录、Key密文 | PostgreSQL通常保留可复用页，后续写入可利用；数据库文件不一定缩小。 |
| 确认清理独占业务库（DROP DATABASE） | 删除该库对应的数据文件，通常释放这部分磁盘占用；控制库审计、API账目及既有备份另行保留。 |
| 运行目录暂存 / 永久清理 | 暂存不释放数据文件；明确永久删除后释放所选目录/容器可回收部分，共享镜像与备份仍占空间。 |

普通VACUUM主要供数据库内部复用，不把它描述为立即归还所有空间；本功能不自动执行会锁表并重写数据的VACUUM FULL。主机空闲空间变化受其他服务写入影响，回执不是精确归因的节省账单。参考[PostgreSQL空间回收](https://www.postgresql.org/docs/current/routine-vacuuming.html)、[DROP DATABASE](https://www.postgresql.org/docs/current/sql-dropdatabase.html)。

## 部署与维护

032为控制库追加迁移，含固定主机、最近3份主机盘点、清理任务；不迁移独立业务库、不默认启用主机令牌或排清理任务。可信运维在应用内执行`tsx scripts/provision-runtime-host.ts rococo-root`或`rococo-root2`生成独立私有配置；只输出成功提示，配置用私有文件安全传到对应主机，禁止进入仓库/日志/页面。

审核后的`integration/runtime-maintenance/agent.py`部署为固定systemd服务，配置位于`/opt/persist/groupdesk-runtime-maintenance/secrets/agent.json`（root:600），本地进度位于同根`state`（700）。代码位于`/opt/docker/oc-projects/groupdesk-runtime-maintenance/releases/<源码版本>/agent.py`，`current`指向确定版本；服务定义见同目录仓库文件。微信/MaiBot/Reader继续Docker部署；这是主机上的受限维护代理，不是新的微信容器，也不修改现有部署方式。

服务仅向固定GroupDesk HTTPS出站，不监听新端口，网页无主机权限。空闲每30秒领取任务/更新在线状态，不自动扫描文件；只有人工盘点或已确认操作才采集元数据。暂存根位于各自原始根内，避免systemd只读隔离的挂载边界造成跨设备移动。旧目录、备份与共享镜像首版无删除入口；将来清理需另设归属/依赖/保留策略，不以文件年龄自动认定可删。

恢复备份前，若主机维护仍在核验或执行，恢复脚本停止并要求先对账。恢复控制库后取消旧的排队/在途维护，清除主机令牌并禁用代理接入；运维重新配置主机后，管理员须重新盘点、预览和确认，不自动重放备份中的销毁任务。

当前两台主机的oc-workplace挂载了`/opt/docker/oc-projects`，因此其下的机器人部署文件会显示其他容器引用并保留；不为了清理放宽这项检查。独立持久化目录和自有容器可在其他前置条件满足时单独选择。


## 旧共用部署的显式退役扩展（2026-11-08）

本节扩展首版的旧目录只读规则：只有RyuBuddy固定UUID经受信运维在root2登记`legacy-ryubuddy-v1`后，其明确专属子目录和4个精确容器才可清理；其他旧目录、部署代码与现有备份继续只读。普通用户不能登记或清理。入口「机器人管理 → 彻底清理」可统一编排业务资料和运行环境；仍可在本页处理原签名主机任务、恢复暂存或核对失败。

安装新版agent后，运维执行`enroll-legacy.py --instance-id <控制面记录的旧运行实例UUID>`。它只读容器/网络/文件元数据，核对固定旧容器名称、Compose项目/服务和允许挂载根，登记容器ID、镜像、网络ID及3个旧systemd单元定义摘要，不读取账号配置或密钥。私有登记保存在`/opt/persist/groupdesk-runtime-maintenance/legacy-ryubuddy.json`，root:600；不自动停止旧服务。容器重建或定义改变后必须重新核对，不静默更新许可目标。

旧账号的maibot-availability定时器/服务与maibot-wechat-routing服务仅在已确认清理时停用。保留旧源码目录；资料按已登记路径移动到各自原根内`.groupdesk-quarantine/legacy-ryubuddy/<任务UUID>/…`，避免跨设备移动。硬链接只有全部链接都在同一选定目录内才允许处理；外部链接、符号链接或未知挂载保留。旧微信目录中有桌面`.bak`时，会将通过核验的顶层子目录单独登记，包含备份的桌面配置与未知文件保留；Reader/backups不登记为清理路径。专属镜像仅在无其他容器引用且Docker允许删除时尝试删除，不force、不prune，共享层/依赖镜像可能继续占空间。

统一彻底清理任务由033控制表保存，与主机队列链接在同一事务提交：主机暂存完成后才清业务数据，最后永久清理主机原暂存范围。手动永久确认涵盖完整已选流程，中断保留原清单；无需删除站点账号。独立部署仍按UUID目录/受限数据库整库清理，旧共用库按明确业务表清理，绝不清空控制库。已有备份不随此功能删除，不承诺所有磁盘占用都归零。
