# 群内回复控制

群的点名方式、话题范围、参与程度、连续轮数、成员跟进和总量预算共同生效。启用话题不代表每条消息必答；明确点名也不能绕过权限、发送去重、模型调用预算或请求时效。

## 连续轮数与跟进

每群可配置连续回复上限、轮数重置间隔和免点名跟进窗口。点名回复算第一轮并重开一段；已经得到机器人成功回复的同一成员，在跟进窗口内可不再点名，仍受轮数和其他限额约束。窗口从最后一次成功发送完成计时，不能从预留或开始生成的时刻计时。其他人、其他群、未确认送达或已过期的记录不授予跟进资格。

停用轮数限制不取消其他预算。点名模式保留上述已确认同人跟进；安静模式继续只接受明确点名。按群保存后需由运行端实际应用，再由管理员手动刷新确认。

## 总量频率与补答

「系统设置」可维护按滚动时间窗口的群回复量、成员间隔及点名补答策略。配置版本经运行端能力确认后生效；普通主动发言和明确点名的处理分别受原生策略约束。补答保留原始来源、首次采集时间、绝对截止、目标群和幂等ID，不把催促或重试当成新任务重新计时。

维护期间的历史补回复必须有明确授权，核对原群记录和发送证据后有界恢复；不会因重启、重新启用或改变配置而自动重放所有旧消息。

## 送达与时间

界面回执为unverified不直接记为成功。Chatlog Reader客户端只能在新发送的有界时间窗，找到同群、本账号、完整正文一致且具有服务器ID的唯一新记录时补充独立送达确认；不改原界面回执，不重发。发送失败或确认不足继续保留待核实状态。

超时、请求总时效和超过阈值的同条回复致歉见[group-timeouts.md](group-timeouts.md)。策略实现分布于`integration/maibot/reply-limits`、`frequency`和原生限额账本，部署工具必须检查实际基线摘要；不能把历史安装器覆盖到已追加修复的运行目录。
