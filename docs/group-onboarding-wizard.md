# 站点内接入已加入的微信群

## 使用流程

1. 先将已部署、已登录的机器人微信加入目标群。
2. 在GroupDesk选择正确机器人，进入「新群接入」（或群管理的「接入已加入的微信群」）。点击「读取微信本地群」。只获取本地群名称与原生标识，不读取聊天正文；联系人库可保留已退群记录，因此管理员须确认账号仍在目标群中。同名群先在微信区分名称，刚入群未同步时等候/发一条普通消息后重读。
3. 选中一个未接入且名称唯一的群。可从空白开始，或参考当前机器人的其他群；选择话题、语言、参与程度、已发布基础与特色、知识库。参考群保留完整语言规则和固定特色版本；基础可固定或跟随最新发布。聊天模型继承默认或沿用参考群，随后可在群管理修改。不会复制聊天、积分、发送队列、互动账本或自动总结计划。
4. 可选AI辅助：在「默认模型」单独配置「新群接入配置助手」，首次升级默认maibot-gpt / gpt-5.5（仅当当前空间已登记可用的对应文字模型）。该路由不属于群聊天阶段，修改它不会递增群配置版本。向导允许本次单独选模型；AI只收到管理员需求、所选群名、可选话题与基础人设名称/ID，不收到聊天、密钥或Skill正文。建议严格校验，只能人工采纳，不授予权限或执行服务器命令。未配置助手时仍可手工接入。
5. 勾选已入群及读取/发送范围确认，查看弹窗摘要后「确认接入」。站点创建停用草稿及持久任务；运行端校验真实账号/群，追加精确白名单、读取与发送映射；成功后才按选择启用。新群直播游标从当时尾部开始，不自动回复接入前历史，不改变旧群游标/Reader epoch/积分/发送幂等记录。
6. 任务进度与记录保存在当前机器人业务库。进行中更新，完成后停止轮询；关闭窗口不会取消已开始的工作。可以刷新、继续失败任务，排队期间可取消。重复提交共享同一记录；候选列表15分钟有效，运行前再次校验。重试可采用最新同一原生群的名称元数据，不会改成另一个群。
7. 绑定成功后继续等待本群revision的真实ACK。可以「检查读取与发送」、打开群管理，或在群里点名验收。「发送入群问候」需另行弹窗确认，走本群真实模型、Persona及发送额度；每个接入记录只允许一条幂等问候，不对未确认送达的消息自动重发。微信扫码、手机确认、解锁及恢复搜索框可见主界面仍由账号使用者在既有桌面入口完成，无需Codex登记。

## 实现与边界

- 新增业务库表group_onboarding_jobs/bindings/agent。队列、候选元数据、租约、重试和模型配置全部按机器人数据库隔离。网站请求需管理员会话/CSRF；运行请求需本账号Bearer及已绑定实例ID/账号指纹。运行端不能选择其他机器人，过期租约不能确认。
- 接入向导面向已准备好独立Docker运行端的机器人；账号首次扫码、加密Reader密钥准备和账号启用仍属机器人部署流程。当前运行的Tatsumi部署后通过专属agent处理。暂停的原账号不因本次发布启用、变更或开始读群。
- 原有「添加群草稿」保留用于提前准备；草稿不等于完成服务器接入。已接入群用群管理维护，不重复登记。
- 模型只推荐配置；真实绑定与授权由固定程序完成。助手输出不能包含API Key、external_id、启用指令或任意执行内容。授权仅追加管理员选定的一个原生群，失败的新群保持停用。
- 新增Docker pull agent，挂载本账号连接配置和独立Unix控制socket；agent以本账号连接文件的UID/GID运行，私有控制目录和socket为同一UID/GID的0700/0600，外层目录root私有，挂载只读；无Docker socket、无数据库/模型密钥、无其他账号目录或对外端口。它空闲只检查任务队列，不扫描微信数据库。发现联系人只在管理员请求时进行，已存在的微信写库事件触发机制不变。
- 受限宿主机broker每实例绑定一个机器人UUID；只允许discover/connect/verify/greeting/progress五种固定操作。拒绝任意命令、路径及跨账号标识，密钥只在既有Reader容器内解包并验证，联系人解密副本仅在tmpfs。网站/模型无法访问broker。
- 接入时检查队列空闲，再暂时停止该账号入场并检查在途工作；仅重载自身读取器、发送适配器及桥接，不重启微信或MaiBot。更新均备份和记录摘要；失败仅恢复本次未被外部改变的配置，不恢复或覆盖活跃SQLite账本，不删除已观察数据或对不确定发送重试。恢复操作同样先检查空闲。
- 同机代理需要直连时，agent只增加自身端点/32与自身bot桥接口匹配的规则；Reader不增加公网网络，原账号规则不变。既有两个runtime端点在桥接重建后由原实例unit重新核对。
- 当前Reader/发送栈的上限是每账号10个精确群；超限、同名、未同步、登录/界面未就绪、忙碌、配置变化等返回可读原因。不会为绕过错误扩大成所有群。

## 一次性运维安装

在按oc-push/oc-prod-release审核合并并部署管理端（应用019迁移）后，将固定发布的integration/group-onboarding及integration/maibot/bots/wechat_egress.py放到rococo-root2对应公开代码目录。运行：

```sh
python3 integration/group-onboarding/install.py <机器人UUID> \
  --source <已合并的40位提交> \
  --python-image sha256:<已经验证且本机存在的Python运行镜像摘要> \
  --agent-image groupdesk-onboarding-agent:<同一提交>
```

安装器校验已有独立账号身份，不处理账号首次取钥，不改任何群配置或启动暂停账号。它离线构建agent镜像，写入独立compose.onboarding.json；broker源码位于/opt/docker/oc-projects/groupdesk-onboarding/releases/<提交>，私有任务备份在该账号persist/onboarding。两份实例unit分别提供受限Unixbroker和agent精确出站。初次安装不重启微信、Reader、MaiBot或现有桥接。后续正常新增群全部由站点任务执行，无需再次运维登记。

## 验证

独立PostgreSQL/合成双机器人覆盖角色隔离、CSRF、候选过期、重复请求、租约、失败/取消继续、仅所选范围追加、默认模型独立、AI非法ID、问候并发去重及模板语言保留。断网Python测试覆盖配置只追加、旧游标保留、失败恢复、重试不重复、忙碌拒绝、外部变更保护、文件权限与问候不确定送达不重发。生产验收先做元数据发现和界面检查；没有用户指定的新群时不凭空创建真实群或发测试问候。

## 按指定群名读取
可在新群接入输入完整群名（例如Shanghai Entrepreneurs Meetup），点击「按指定群名读取」。这是当前账号本地元数据精确匹配，忽略大小写、兼容字符和多余空白；同时匹配群名称、群备注和缺少联系人时的会话标题，不发送群消息、不创建配置或拓宽授权。查询先匹配再截取500项，避免列表较大时漏掉目标；同名警告按完整集合计算。读取完成会显示查询名、匹配数量和时间，任务历史保留每次查询；重新进入恢复最近成功结果。入群后的同步由服务器微信完成，后台每次点击读取最新数据库和已提交WAL；服务器微信离线、未同步或本地没有名称时仍可能暂时查不到，不能凭人工输入虚构群标识。

## 必做步骤与可选操作、刷新恢复
1. 选择已加入的微信群（必做）。
2. 检查话题、人设、模型、语言等配置并确认接入（必做；AI建议可选）。
3. 系统完成绑定并等待机器人确认当前版本（必做、自动执行）。接入已确认后即完成必做流程，群是否启用仍遵从管理员选择。
4. 检查读取与发送（可选，不发送群消息；可按需重新检查）。
5. 发送入群问候（可选，会实际发送，保留独立确认；已有问候任务改为查看进度/结果，不额外重发）。
6. 进入群管理（可选，用于以后维护）。
第4、5、6步不要求依次点击，也不要求全部完成。页面上方始终保留当前群的完整流程，执行细节可展开；查看问候或检查子任务时仍保留所属接入流程。浏览器按机器人、按标签页记住已提交任务ID和是否停留在新群接入页；刷新或同标签页重登恢复流程及当前可选操作结果，不保存未提交表单。后台另列接入流程摘要，独立于最近30条操作记录，因此多次读取群名不会把原接入流程挤掉；所有读取仍限制到当前机器人业务库。进行中的子任务恢复只继续查询状态，不重新创建或发送问候；完成后停止自动查询。
