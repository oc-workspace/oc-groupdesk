# 多机器人管理与独立业务空间

## 现行规则与站点接入向导（2026-11-07）

每个用户账号当前最多启用一个微信机器人；不同用户互不暂停、互不抢占。机器人归属决定启用配额，管理员代操作也遵守目标所有人的限制。拥有`bots.manage`权限的已审核用户可以启用自己的机器人；审核通过本身不自动授予创建/管理权限。

普通用户添加/编辑时只填管理名称、微信号、备注；部署服务器标签不再展示、下发或允许通过API修改。默认仍使用原有`rococo-root2`备注，不据此执行部署。管理员保留「部署位置备注（不执行部署）」；服务器分配、一键安装、Docker权限、远程桌面代理均未在本次引入，现有部署目录、工具和登录方式保持。

新建机器人自动生成服务器持久化接入任务；刷新、退出登录后可从「机器人管理 → 继续接入」找回。原有机器人不自动创建任务或重新取钥，可按需打开向导。页面只手动刷新，异步操作展示loading/错误并允许重试，重复开始不会重置已完成步骤或创建第二套环境。

| 编号 | 步骤 | 完成依据 |
|---|---|---|
| 1 必做 | 保存微信资料 | 独立业务空间登记完成；不代表Docker已部署 |
| 2 必做 | 准备独立运行环境 | 管理员按现有工具准备独立微信桌面，记录准备结果与专属登录入口；真实连接另查 |
| 3 必做 | 登录并确认微信账号 | 本人扫码/手机确认后，由当前所有人在站点明确确认登记账号；不把填写微信号当作协议身份验证 |
| 4 必做 | 授权聊天读取 | 当前所有人单独确认本账号读取、必要受控启动取钥及账号私有Reader加密保存，保留操作者/时间/范围审计 |
| 5 必做 | 检查微信与机器人连接 | 管理员完成首次群绑定、Reader和运行端；真实指纹绑定、当前版本、90秒内微信/Reader/MaiBot上报与local_ready必须满足 |
| 6 必做，可提前 | 配置Key与文字模型 | 默认文字或四个运行阶段选择完整，凭据启用、模型目录和所有人/公用授权校验通过；不试调用、不消耗token，不保证尚未实际调用时的余额 |
| 7 必做 | 启用机器人 | 只暂停本用户原机器人，等待精确版本及发送/队列/处理清空确认，再启用；记录首次接入完成时间 |
| 8 可选 | 查看微信群与继续接入 | 查看已绑定群；后续新群仍进入现有「新群接入」向导 |

现有`start_stack.py`完整启动要求至少一个群白名单，**首个群绑定仍由管理员配合按现有部署流程完成**；不能承诺零群自动启动或仅点网页即完成部署。此处未放宽现有运行端校验，也未自动取钥、安装容器或发送测试消息。登录页提供二维码失效、手机确认/锁定、入口打不开/网络断开、登录错误账号等指引。本机`127.0.0.1:18080/18180`入口明确提示只有已开通隧道的当前设备可用，不冒充普通用户通用公网入口。登录URL不接受密码、查询令牌、片段及任意明文HTTP；管理员不必向普通用户暴露SSH、Token或密钥文件。

账号确认和读取授权不能由管理员代其他所有人勾选。更换尚未绑定的微信号或部署备注会清除原确认及环境记录；暂停后转移归属也清除原所有人的确认。启用/暂停/归档等生命周期在事务锁内重新核对所有人，归属变更只允许已确认暂停或归档且没有待切换的机器人。切换可取消，已开始暂停的旧机器人不会自动恢复。

控制库迁移`026_bot_onboarding_bot_control.sql`将全站单行切换改为`owner_user_id + activation_slot`，保留升级前待切换目标；若已有任务归属缺失则事务失败，不静默丢弃。当前API只允许slot 1，数据库约束同一所有人/槽位最多一个active或pausing。预留槽位支持以后扩展多机器人配额，本次不提供提高额度入口。新控制表不复制到业务库，不向业务角色授予访问。

## 总管理员删除登记与群配置（2026-11-08）

总管理员在「机器人管理」卡片点「删除微信号登记」，或在「群管理」选中群后点「删除群聊配置」。普通用户即使拥有创建/管理权限，也不显示删除入口；删除影响预览和DELETE接口均由服务端验证super_admin。弹窗先读取当前版本、影响范围和阻止原因，必须选择删除原因（测试号、违规、重复、不再使用、其他）并完整输入微信号或群名才能确认；补充说明和操作者写入审计。未保存的群编辑需先保存或还原。

删除与归档分开：归档可恢复；删除后不再出现在正常管理入口，原ID的管理、恢复、共享、授权和运行访问均拒绝，界面不提供恢复。微信号/管理名称及群绑定可重新登记，但得到新的ID和独立空间，不挂载或继承旧账号数据。删除登记采用保留标记，**不是物理擦除全部数据**：必要审计、历史素材/积分、API用量账本及底层账号资料留存，既有Docker、微信账号、微信本地聊天和真实微信群均不自动操作；用户独立拥有的Key、授权和其他机器人资源不删除。后台历史用量将原机器人标为「已删除」，删除不释放已消费额度或抹掉未知金额。

机器人需暂停或归档；已接入账号必须有可信停止与队列/处理中清空证明，无等待切换、正在计量的模型调用或正在执行的后台作业。尚未接入、刚保存的登记可直接删除。删除撤销适配器凭据，取消未开始任务与待审批Key申请；业务空间不再被worker遍历。删除原RyuBuddy登记不会删除控制库管理员、OAuth或Key，也不会破坏启动。

已绑定群需先暂停所属机器人并等停止确认，删除后可重新启用剩余群。群删除停用计划和未开始任务、撤销成员及私聊场景授权，解除话题/知识库/人设绑定；独立资源保留。原运行端仍能读取该群的禁用通知并ACK（仅用于移除配置，不开放对话、模型或知识访问），避免一个已删除群中断其余群同步。正常群列表、人设绑定、总结、互动和Key分配选择器不再展示它；本地微信发现仍可能列出该真实群，可再次明确接入。

027为控制库的登记删除标记及存活名称唯一索引；028为各业务空间的群删除标记及存活群标识索引。生命周期/模型预留在事务内再次核对有效登记；删除使用全局生命周期锁和行版本锁，确认页过期或并发重复删除不会改到其他对象。角色、Key和跨机器人数据边界维持，删除操作记录审计。

## 首版历史范围（2026-11-05）

当前微信账号为RyuBuddy，服务现有三个群。增加第二个微信账号后，第一个账号暂时停用；首版按先后切换使用，暂不做并发容量评估。开发及接入准备期间不自动停用RyuBuddy；待新账号接入并明确切换后才暂停旧账号。暂停保留配置、素材、聊天、积分、账本和计划，允许以后恢复。

一个微信账号对应一个机器人实例；同一账号按群切换Persona仍是同一机器人。微信号、后台管理名称和Persona名称分别维护，以稳定机器人UUID作为系统主键。RyuBuddy身份依据用户确认登记，不通过人设昵称猜账号。

## 产品与部署

统一GroupDesk管理机器人目录和管理员登录。新增机器人有独立业务数据库/数据库用户、资料目录、模型加密密钥和适配器凭据；原账号兼容迁移安排见下文。机器人端各自使用独立Docker项目、微信桌面/登录目录、Chatlog Reader/加密密钥、MaiBot和消息桥，不互挂账号数据，不共享发送队列和对话记忆。当前服务器角色保留：root运行管理端，root2运行微信栈；未来可连接其他运行服务器。

后台「机器人管理」支持创建、编辑身份与部署标签、查看接入状态、暂停、恢复和归档，并选择所管理的业务空间。新增机器人默认暂停且待接入；初始化空业务库，不自动复制旧机器人的Key、素材、Persona、积分或定时任务。复制/分享是后续独立明确操作。停用和永久删数据分开；首版提供可恢复归档，不提供一键永久清空。

所有群、话题、模型/Key、知识、素材、Persona、互动、总结计划/结果、通知配置和审计属于当前业务空间。运行端Token映射机器人与精确群白名单，不能通过请求头切换到其他机器人。浏览器管理请求明确选择机器人；切换清除旧空间组件和在途视图，不把旧表单保存到新空间。

## 切换与任务

现行每个用户同一时刻只启用一个机器人，不同用户独立。启用同一所有人的新账号前验证业务库和接入能力，先暂停旧账号并等待在途发送安全结束/确认暂停，再启用新账号；不会靠超时猜旧账号已经停止。新旧账号独立记录配置确认，失败保持新账号未启用并给出原因。

暂停后停止新的入站处理、自动总结和发群，不篡改群原有启用开关。原定时计划保留；恢复时每日计划计算下一次执行，已错过单次预约转待检查，不自动补发。重新启用按当前来源尾部恢复实时消息，不把暂停期聊天当作新消息重放；历史仍可供手动总结/素材处理。

不同机器人即使进入相同微信群，也有各自群配置和账本；同一用户当前先使用一个活动账号，不实施该用户的多机器人同时发言或自动主备抢占。

## 首次迁移与验收

RyuBuddy接管现有业务库、资料目录、模型主密钥、适配器、三群和全部历史，不复制或重建用户配置，不重复创建总结计划。新增业务空间从空库初始化，通过数据库权限、服务端作用域及文件目录共同隔离，控制面管理员可以有意切换管理全部空间。

验收使用独立测试数据库、合成双机器人、并行请求与固定镜像断网副本。覆盖跨空间ID/Token/文件/模型拒绝、暂停时模型和发送失效、切换确认、重启恢复、计划恢复与不重放。真实第二账号的接入需用户提供账号并完成登录，不能用假状态冒充已接通。

本节保留首版迁移依据；现行按用户切换与站点向导见文档开头，具体测试及发布证据见每日进度。

已删除站点账号可另行在「用户管理 → 已删除账号与数据清理」预览、清除符合条件的独占独立业务库及目录；原兼容共用库、共享和其他作者内容保留，详见[用户与权限](users-and-permissions.md)。已物理清除的业务空间不再备份或重建。

## 首版实现与使用

左侧「当前管理的机器人」只切换管理空间，不改变活动微信账号。进入「机器人管理」添加账号后，可以分别管理群、模型/Key、话题、Persona、互动和总结。新空间不含旧机器人的这些资料；内置话题目录与互动模板作为程序公共模板初始化。创建、编辑、接入白名单和生命周期操作记入审计。状态需要手动刷新。

RyuBuddy的数据库迁移有一个兼容安排：保留原库中的现有业务表及原文件路径，避免搬移运行中的历史和账本；业务连接改用受限用户，无法读取同库中的机器人控制表、管理员口令和登录会话。控制面连接可管理各空间。新增机器人从首版起使用独立数据库、数据库用户、文件目录和模型加密主密钥，不使用此兼容安排。

新增机器人处于暂停状态时，在「接入配置」生成一次性专属Token，再选择本空间已绑定的群白名单。Token不回显，轮换会撤销旧连接、清空旧运行实例绑定。部署标签仅是管理备注，不会让网页在指定主机执行命令。首版容器安装由运维工具完成，不是后台一键自动装微信。

「启用并切换」要求目标最近90秒内回报当前版本的微信、读取器、MaiBot均在线，本地控制允许运行，且没有在途任务、发送锁和发送队列。旧机器人没有明确回报停止时，界面保持等待，不凭超时推进。归档是暂停后的可恢复操作，不删除数据。暂停仍允许管理员明确提交资料解析、Persona生成和讨论分析等后台作业，自动群互动和总结发群停止。

## 新账号Docker接入工具

`integration/maibot/bots/render_stack.py`接收JSON清单，生成空的独立Compose部署，不复制任何现有账号数据、不启动服务。清单字段：

```json
{
  "bot_id": "后台新建机器人的UUID",
  "wechat_id": "用户确认的微信号",
  "ports": [18101, 18180, 18543, 18187],
  "images": {
    "maibot": "sha256:已校验的本机镜像摘要",
    "wechat": "sha256:已校验的本机镜像摘要",
    "reader": "sha256:已校验的本机镜像摘要"
  }
}
```

端口顺序是MaiBot管理页、微信桌面HTTP、桌面HTTPS和发送API，均绑定127.0.0.1；使用前检查未被占用。部署位置固定为`/opt/docker/oc-projects/groupdesk-bots/<不带横线的UUID>`，持久化固定为`/opt/persist/groupdesk-bots/<同一UUID>`。每套Compose自行创建网络，Reader数据网络为internal，不接入原账号的网络。

运维顺序：

1. 用实际新账号ID在后台建空间，再生成部署清单与空目录。先准备本账号的`secrets/desktop.env`（CUSTOM_USER、PASSWORD），仅启动`compose.desktop.json`中的微信；由本人扫码/手机确认。
2. 基于已审核版本准备本账号的`runtime/bridge`、`runtime/limits`、`runtime/bowxt`和`runtime/patched`，每个部署文件列入`runtime/SHA256SUMS`；不能复制原账号的策略、Persona或密钥。准备独立MaiBot配置、厂商协议确认、群白名单与基础人设。
3. 在本账号登录目录定位db_storage，配置自己的Reader、加密取钥及独立API Token。此操作在账号提供后另行执行，不能以旧账号密钥代替。`.env`只含`READER_ACCOUNT`与`WECHAT_ACCOUNT_DATABASES`，后者必须在本机器人的wechat目录内。
4. 私有`groupdesk/connection.json`除url、token、groups外，加上bot_id、wechat_id、生成的runtime_instance_id，以及Reader账号目录名SHA256作为account_fingerprint。该指纹用于绑定所配置的数据库来源，不等于通过微信协议验证公开微信号；实际账号由本人登录与运维核对。后台Token和各群白名单必须与本空间一致。
5. `start_stack.py <部署目录> --desktop-only`用于首次桌面登录；完整运行使用`start_stack.py <部署目录>`，会先校验固定目录、代码摘要、私有配置、Reader与连接的账号/群绑定及只读原库挂载。缺项时停止启动。不会自动启用后台机器人。
6. 收到真实健康上报后再按用户要求切换。用户已登记Tatsumi/Tatsumisaki，独立桌面已启动；Reader与MaiBot仍待本账号登录和配置，不暂停RyuBuddy，不宣称第二账号已连接。

独立运行栈的微信缓存、Reader密钥、Chatlog归档、MaiBot记忆、发送证据及账本都放在其私有目录，不能只备份GroupDesk。公共镜像可以复用，登录目录与业务数据不能复用。

## 备份、恢复与运维脚本

GroupDesk `backup.sh`暂停应用写入后，一起备份控制库、所有ready业务库、文件及根模型主密钥，并记录摘要。`restore.sh`先校验摘要及主密钥，使用加密控制元数据重建受限数据库身份，再按各自身份恢复业务库。恢复后所有未归档机器人保持暂停；归档状态保留。启动失败时应用保持停止，不能以部分恢复的数据继续发群。全新灾备恢复需要当前版本镜像，且必须保留本次备份的模型根密钥。

受信运维导入脚本统一通过`tsx scripts/bot-exec.ts <bot UUID> <允许的脚本名> ...`选择目标空间，避免把第二账号的素材导入默认空间。脚本只允许已有的明确导入/维护命令，不提供通用Shell执行。


## 新桌面显示“网络连接已断开”的检查与直连

远程桌面HTTP认证/画面正常，不代表里面的微信已连通腾讯登录服务。2026-11-05核对Tatsumisaki时，新容器能完成TCP握手，但腾讯公开HTTPS连接被重置；同机RyuBuddy可正常HTTPS。原因是服务器sing-box策略路由默认接管新Docker流量，而原账号已有独立直连规则。不要把此问题当成桌面密码错误，不要关闭认证或接入旧账号网络。

已审核工具`integration/maibot/bots/wechat_egress.py`只对指定新机器人当前微信容器的私网IPv4 /32和其独立Docker桥接口，同时匹配后使用main路由表，优先级8995。它核对UUID、部署目录、Compose项目/服务标签、独立网络及IP归属；不修改代理、过滤规则、端口、Reader内部网络或其他服务路由。工具只读取Docker连接元数据，不读取微信账号/聊天、desktop.env或容器环境。

## 经明确授权复制配置

## 独立账号读取器与运行端出站

`integration/maibot/bots/capture_reader.py check <机器人UUID> --bootstrap-image sha256:...`校验固定部署目录、账号指纹、连接/Reader群范围、自己的微信进程用户和已核验的启动取钥工具；只对自身测试子进程预检，不停止微信、不获取密钥。`capture`另需`--authorized-account-key-capture`，必须事先取得针对该账号的明确授权；它只允许首次接入且MaiBot/桥接未运行，拒绝原账号UUID及已有密钥自动重取。

取钥复用经验证的Docker启动观察器，仅在该账号的微信容器内以UID1000临时运行；传入公钥，密钥在内存中校验并加密，本账号独立密钥库验证HMAC后保存信封。退出恢复本账号微信、清理临时公开工具和加密中转，不暂停其他机器人、不修改旧密钥、不启动发群。该过程可能再次要求本人确认手机登录。永久Reader仍为独立Docker服务，只挂载本账号数据库及明确群白名单。

同机sing-box默认出站异常时，微信直连工具另可指定`--service maibot`或`--service wechat-bridge`；仍只匹配该容器/32和其自有bot桥接口。`groupdesk-bot-runtime-egress@.service`分别维护这两个精确规则，状态与微信规则分开保存；不授予Reader出站，不加入其他机器人网络。新运行容器启动后启用该实例，容器重建后重新启动以重新绑定地址。

## 两种删除方式与已删除机器人（2026-11-08）

总管理员在机器人卡片选择「删除登记（保留数据）」或「彻底清理（释放空间）」。前者保留底层数据，弹窗中的群/话题/人设/知识库数量是关联统计，不是物理删除清单。后者单独读取影响预览，勾选业务或运行环境、选择原因/说明、完整输入微信号并勾选永久删除后排队；不要求先删除站点用户。未删除的机器人仍须暂停且有可信停止证明，提交后先删除登记再处理已确认范围。若登记已移除而后续排队/执行失败，可在已删除列表查看、继续处理，不提供登记恢复。

「已删除机器人与彻底清理」始终保留入口，手动刷新显示任务阶段、错误及保留项，失败按原范围重试，不覆盖已有不可逆进度。共享或其他作者资源保留，独立业务库沿用精确UUID/目录/角色检查；Key所有权、公用授权与真实计费账本独立保留。所有任务、原因、操作者和结果写审计。

RyuBuddy另有冻结的旧部署配置：站点共用数据库不DROP，只在无共享/其他作者资源、无清单外外键/触发器且绑定正确时，TRUNCATE明确旧业务表（RESTRICT，禁止CASCADE），保留admins/sessions/managed控制表/audit_logs/迁移标记与默认模板。包含共享内容时业务资料整套保留，需先处理归属，不自动拆分迁移。登记资料文件只能是数据库引用的uploads/persona内规范单文件，核对路径、inode/设备/大小/修改时间/硬链接；Tatsumi的bots子目录和未知文件均不遍历删除。表清理与进度标记同事务，文件按原清单续作；旧受限数据库角色禁止新登录，不删除站点主密钥。

运行环境使用现有主机签名任务：先停止并隔离，再按本次明确的永久清理授权执行删除；不依赖保留天数，不另创建同盘全量副本。4个旧容器、网络和服务必须由受信运维登记精确ID及定义摘要。只处理旧专属资料；共享镜像、其他账号、部署源码、原备份和未知文件保留。细节见[运行环境维护](runtime-maintenance.md)。

彻底清理进行中，不允许从主机维护页另行还原或改变同一机器人范围。失败且业务清理尚未开始时，可撤销原范围再重新预览；数据库或文件已开始删除时只能核对并续作原清单。未迁移进独立Key管理的旧API凭据会阻止业务清理，避免误删用户仅存的Key。


## 接入过程的 AI 与模型准备指引

添加机器人表单及接入任务标明：保存资料、准备环境、微信登录、授权读取、连接检查和启用操作本身不调用 AI；第6步仅配置 Key/文字模型并检查授权，不试调用模型。正式启用前仍必须通过文字模型检查，启用后生成聊天回复等会消耗所选 Key 的额度。

第6步提供流程内「添加自己的 Key」「申请公用 Key」「配置当前机器人模型」入口：Key 保存后先查询目录或手工登记模型，再选择 Key＋具体模型并保存。公用 Key 需要管理员授权群回复；新增 Key、申请获批均不自动设为默认，也不自动借用管理员私有 Key。没有模型管理权限时显示联系管理员并禁用设置入口。

设置面板明确显示目标机器人，模型请求固定绑定该机器人，不随其他页面选择改变；返回后重新检查接入状态。未保存的 Key、申请或模型修改在离开设置面板前提示确认，原接入任务保持。此为界面指引，不自动创建 Key、申请授权、生成回复或启动微信环境。
