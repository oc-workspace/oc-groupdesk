# 新增服务器微信群

创建 GroupDesk 群空间只会创建配置草稿，不会自动扩展服务器读取、发送或适配器授权。新群需要先完成一次精确绑定；不能把群昵称直接填作可信群标识，也不能为方便而开启所有群。

## 首次绑定

1. 将机器人账号加入目标群，在服务器微信的联系人数据库中确认群名称唯一对应一个真实 `@chatroom` 标识。重名时需明确指定真实标识，不能猜测。
2. 备份服务器私有配置和 SQLite 账本，暂停新消息入场，确认没有在途模型任务或发送队列。
3. 为目标群增加 Bowxt 精确群名授权，独立重载 Bowxt 服务后通过 `POST /api/chats` 注册本地聊天 ID。无需重启微信登录进程。
4. 保持以下配置一致：桥接 `WECHAT_ALLOWED_GROUPS`、`bridge/groups.json`、`groupdesk/connection.json`、Bowxt `allowed-chat-names.json`、Chatlog Reader `config/reader.json`，以及 GroupDesk 对应 `runtime_adapters.group_external_ids`。
5. 可信群标识采用该适配器的命名空间，例如 `bowxt-root2:<local_chat_id>`；仅追加目标群，保留原有群的映射和授权。
6. 重载读取器，确认目标群唯一绑定且健康；仅将新群直播游标初始化到当前尾部，不重置旧群游标，不回放历史消息。保留归档 epoch、积分和发送账本。
7. 通过原 Compose 文件和 Chatlog Reader 网络叠加文件重建消息桥，恢复入场开关。保留写库事件触发，不添加空闲数据库扫描定时器。
8. 在 GroupDesk 的「群管理 → 目标群 → 连接与互动设置」填写可信群标识并保存。勾选需要的话题、打开「启用此群机器人」，再保存。

所有凭据及带凭据的连接文件只保留在服务器私有备份中，不提交仓库或输出到终端。

## 验收

- 刷新确认状态后，`已保存 vN` 与 `机器人已应用 vN` 一致，并显示「机器人已确认」。
- 配置确认与启用是两个状态：停用配置也应确认；收到确认不代表群已经启用，需要同时查看启用开关。
- 未启用群的同步不请求模型凭据；启用群仍须取得并校验当前版本凭据才能确认，失败时停止处理，不回退旧权限。
- 核对读取器授权群、消息桥群映射及适配器范围完全一致，原群版本、直播游标和密钥保持不变。
- 数据读取接入和配置确认可用只读检查验收，无需发送群测试消息。
- 发送器需要主界面搜索框可见。远程桌面建议固定 1920×1080、100% 界面缩放，避免自动高倍缩放触发窄屏聊天布局；锁屏时应由账号使用者解锁。
- 界面回执 unverified 不等于没有发送，禁止盲目重发。必要时只读核对目标群原始数据库中的唯一服务器确认记录，保留原回执与独立确认依据。

此流程目前由服务器运维完成。后台创建群与填写群设置不能替代第一次服务器绑定。
