# 服务器版群聊总结

左侧「群聊总结」按群维护设置，独立于基础Persona与特色Skill。保留原Mac/Hermes总结，不改变原来的采集桥或Skill。

## 使用

1. 选择群、模板、语言、时区；默认继承本群文字模型，可单独选择API Key和联动模型。保存配置。预览不需要允许发布。
2. 手动范围支持昨天全天、当天截至执行时刻、最近24小时、指定日期全天、自定义跨日起止时分。日期按所选时区解释，左闭右开，最多31天；尚未结束的时段不能提前生成。
3. 「生成预览」只生成正文；点击刷新查看任务，打开预览后可人工修饰。「发布这份预览到本群」不再调用模型。「立即总结并发布」生成成功后自动加入发群队列。
4. 自动计划分别配置发布时间和总结范围。每日00:10配昨天全天是常见组合；单次预约执行一次后自动停用。每日计划使用固定历史日期时会重复同一范围，界面明确提醒；需要一次性报告用单次预约。计划内容改变时停用旧计划并另建。
5. 群总结发布和所有新计划默认关闭，不自动替用户选择群或发送。页面仅手动刷新。停用发布或修改时区会停用原计划，检查后可重新启用。保存群总结设置会使旧设置下待处理任务/预览失效；模板修订仅影响后续新任务。

## 数据与执行

GroupDesk位于rococo-root，任务经现有受控HTTPS连接由rococo-root2的机器人桥拉取；使用基于chatlog-keeper的Chatlog Reader，读取服务器微信数据库的授权群存档；统计与分页均为内部数据库API，不是微信GUI翻页，不依赖Mac，不把机器人记录转交Hermes。Hermes本轮不改动。

仅使用服务器已采集记录，不保证微信历史完整。优先原始时间，缺失时以首次采集时间归档，程序显示此类消息数。没有发言人的记录计入总量，不参与个人排名；显示名不等于微信账号，不能识别改名或同名成员。消息正文是资料，不执行其中指令，不访问所分享链接。未确认的发送记录及之前生成的总结不进入新总结，避免自我复述。

取数前先按群和半开时间范围统计合格记录条数、正文字符数和最长单条，排除旧总结及未核实发送；一次主动同步后固定来源epoch与序号上界。根据平均文字量规划每批1—200条，分页只读事件驱动存档，不重复核对原微信库。材料以有界小批上传、顺序和摘要校验、幂等确认；完整条数和正文量核对通过后才进入生成，缺批、重复来源、跨群、越界或统计变化均不使用部分材料。任务记录显示预检查与已读条数/批次，仍仅手动刷新。

单任务最多20,000条、正文200万Unicode字符、单条2万Unicode字符；临时上传总量最多16MB，超限按具体原因提示，不抽样冒充完整窗口。单次模型材料预算默认60,000字符，可按群在24,000—100,000间调整；这是材料预算，不是精确token计数或模型上下文能力探测。昵称表和字段说明只写一次，时间按本群时区转换，减少重复元数据。材料在预算内时统一总结全天；超限按实际材料长度分段，保留有界边界上下文、来源ID、话题进展和未决线索，再统一合并跨时段同一话题。中间归纳仍超预算时继续归并，最多64个原始分段、96次模型请求、任务总计最多60分钟；分段会增加模型调用与费用。原始统计和排名始终按去重后的全天来源计算，不能累加边界重复上下文。模型输入不含密钥、旧会话或其他群。完成取数后清除临时批次；生成结束/失败/取消后清除任务中的原始消息，保留正文、程序统计、进度和来源说明；中断批次在任务结束或租约失效后的清理中删除。原始采集存档仍由现有微信采集器管理。

五个服务器模板（综合、技术职场、发言排名、娱乐排名、资讯排名）可人工维护，部署不覆盖已改内容。首版排名为服务器采集记录发言条数前五个名次，包含并列；不声称具备原Mac版的三榜等全部能力。

每次模型请求最长10分钟，活动生成按租约续期并检查取消与模型变更；中间归纳失败不生成最终正文、不发布。每群滚动24小时生成20次、发布10次，失败不自动重新调用模型。生成、取数和发送有持久状态与租约；预约晚超过1小时不补发，在计划显示错误并停用。后台调度独立于其他文档/Persona任务。长报告最多8段，每段<=2000字符，逐段预留与确认；重复或不确定的发送不会自动重放。Bot和群处于启用状态、目标群与版本、语言及总结发布开关仍需在发送前验证。

## 验证与发布

单元测试覆盖时区、日界线、跨日分钟、未来/错误范围、统计与分段。独立PostgreSQL验证权限、群隔离、预览/直接发群、租约、版本失效、不可重放、单次预约及模板保留。原生测试使用固定MaiBot镜像、无网络和模拟发送；自动化测试不向真实群发送；人工实群验收仅按用户指定在ssh外语学习园地发送1条，Shanghai不发测试。

源码经开发机oc-push、发布桥oc-prod-release、核对PR准确head与规范化diff后合并，备份生产数据库/素材并校验后用既有Docker脚本发布。原生仅新增limits/summary_runtime.py并安装bridge/app.py的两个循环钩子，摘要预检、备份、空闲时仅重建bridge；微信与MaiBot容器不重启，不新增网络或端口。

## 发送待核实

微信客户端未登录或需手机确认时，采集存档仍可能可读，但实际发送受安全锁阻止。先恢复远程桌面本机转发与微信登录；已经提交到微信服务的原消息可能在恢复后送达，不能因后台显示超时而再次点击发布。依据原client_id、目标群、正文摘要和微信verified回执人工核实后，可由运维更新任务状态并留审计。首版不自动重放不确定消息，也不自动推断其已发送。

## 时间与发送者来源保护（2026-11-02）

消息发送时间、服务器首次采集时间、总结生成/发群时间互不等同。原始时间缺失时仍可按采集时间选择归档窗口，但不将采集时刻交给模型当作发言时刻：模型输入中的sent_time为null，仅保留顺序和缺失说明。原始时间可靠时由程序统一转换为所选时区后再提供，模型不再自行转换UTC。

生成报告的具体HH:mm必须属于原始时间来源，否则本次失败且不发布，避免把UTC采集时间直接写成事件时间。无原始时间的消息只总结内容，不写精确发言时分。缺昵称时明确“发送者昵称未获取”，禁止按相邻发言、文字风格或头像相似度猜人名。程序在报告来源说明中附上未获取昵称的记录数，缺失者仍不参加排名。

采集器的有限重试及队列修复可减少未来缺失，不能凭空补出已经不可见的历史昵称或原始时间。原生入站与总结共享服务器存档；本机核对只用于个别用户授权的运维取证，不成为自动运行依赖。历史已发报告不自动重发，避免重复刷群。

## 自适应取数部署（2026-11-04）

数据库迁移017仅新增进度列与临时批次表。旧取数上传接口保留兼容，新数据库来源走source-plan/source-batch/source-complete。旧失败任务保持失败，不自动重试、发群或更改计划。预检查不调用模型；即使生成后发群任务读取失败也不会创建发布分段。

GroupDesk遵循既有生产发布脚本。Reader离线复用已验证codec镜像，只覆盖审核后的公开读取器源码；deploy-summary-batches.py校验准确提交、镜像和代码摘要，暂停新入场、等待已接受任务结束，备份并quick_check归档/游标/限额账本，仅重建Reader和bridge。保留微信/MaiBot进程、账号密钥、群设置、积分、epoch与游标；失败只恢复代码与镜像，不回滚实时账本，不新增网络和端口。
