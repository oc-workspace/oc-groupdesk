# 独立安装打包方案与进度

文档整理日期：2026-11-22（UTC+8）。当前版本为 RC6 验收版；以下测试结果来自 2026-11-20，本次只核对文档、产物与开发分支，不把历史验收写成本日重新测试。

用户安装说明统一放在 [发行包说明](../distribution/README.md)。本页记录开发和验收约束，避免与操作指引重复。

## 打包思路与两种交付物

目标是让其他安装者得到一套独立的 GroupDesk，不带原站点的机器人、群聊、聊天记录、用户、付费 Key 或私人 Persona。系统代码/镜像与私有恢复数据分别保存，新安装与恢复已有业务是两条不同流程。

| 对比 | Linux amd64 离线安装包 | 干净源码包 |
|---|---|---|
| 内容 | 同一套干净源码、安装工具及预构建的站点/数据库镜像 | 干净源码、安装工具及构建配置；不含预构建镜像 |
| RC6 大小 | 312,459,037 字节，约 312 MB | 720,951 字节，约 0.72 MB |
| 安装方式 | 校验并解压，导入镜像，再初始化新实例 | 校验并解压，在目标架构构建镜像，再初始化新实例 |
| 构建联网 | 无需联网下载构建依赖 | 首次构建通常需要联网，或预先备齐缓存 |
| 用途 | 已验证 Linux amd64 设备直接安装/测试 | 开发修改、自行构建；其他架构仍须验收 |

离线包中也有源码；体积差异主要来自 Docker 镜像。“离线”只指镜像已备齐，调用 AI、GitHub 登录或下载机器人组件仍可能需要联网。两种包都需要目标设备具备 Python、Docker/Compose 等前置条件，均不自动安装或登录微信/MaiBot。

私有资料另分两层保管：

- 站点业务恢复：控制库、机器人业务库、素材文件和匹配的密钥/配置，供新空实例恢复。
- 机器人运行环境恢复：微信本地目录、Reader 密钥、MaiBot/桥接等，按宿主机独立备份；不能仅靠站点备份恢复整台机器人设备。

2026-11-20 的分主机私有备份为 4 份加密归档，合计约 13.78 GB，配套口令独立保存；原版本/镜像亦留作回退材料。这些均不附在安装包中，也不上传 Git。索引和口令位置保存在私有备份记录，不在项目文档复制秘密。

## 发行边界

发行包由 `scripts/package-standalone.py` 从显式白名单生成：server/shared/web/migrations/catalog、必要 integration 源码、独立安装工具及原生下载依赖。逐文件 SHA-256、依赖闭包和敏感内容检查后输出源码包；离线镜像仅从该源码和官方 Node/PostgreSQL 基础镜像构建。

不收录数据库、上传/素材、微信群、账号、Key、微信登录资料、截图、进度日志或私有 GT Skill，也不把运行容器提交成公共镜像。第三方 Persona/Hermes Skill 原始文件不随包分发；发行版五份基础总结模板独立编写，已恢复的管理员模板和发布 Persona 仍由私有数据库提供。项目公开许可/渠道另由所有者决定，本次不公开仓库。

新安装：只有本人设置的总管理员；机器人、群、话题实例、知识库、模型 Key、人设、历史材料和运行主机为空。公共话题目录可由用户显式导入。固定旧账户的种子迁到测试夹具，生产初始化不再创建个人账户；旧数据升级仍保留已登记资料。

## 部署与兼容

`distribution/manage.py` 使用独立 `gd-` Compose 项目、新目录、私有配置及本机回环端口，不依赖原站点前端共享网络。init 拒绝已有目录/同名项目/端口冲突，自动生成独立密钥；管理员密码隐藏输入。PostgreSQL 引导角色与应用角色分离，备份恢复时可先在空实例还原原角色。

普通部署与隔离模式分开：隔离模式两个网络均无公网出站、工具禁止启动 worker，某些 Docker 版本不转发内部网络端口，因此验收使用容器内 HTTP。新站点默认也只启动数据库和网页，worker 必须显式启用。运行主机 ID/站点地址可配置；注册默认没有清理权限，未知路径/触发器/共享资源保护仍有效。

已验证 Linux amd64 Docker。Mac/Windows/ARM 尚未做本次整包端到端实机安装；Windows 指引先使用 WSL2，ARM 可使用源码在目标架构重建。站点包不自动安装或登录微信；微信、Reader、MaiBot 与发送桥接仍走各自接入流程，运行目录另行备份。

## 备份恢复契约

备份范围为本站控制库、所有机器人业务库、角色/权限、资料文件、配套加密配置和各服务实际镜像（允许 app/worker 不同版本）。只暂停本实例原运行服务，完成后恢复。GPG 加密后完整解密并逐文件核验；口令独立保存，不进入安装包。

restore 只写新的空实例。支持本工具格式和维护备份 `site` 格式；原始表指纹在迁移前逐表核对，恢复后再用新包迁移。数据密钥成套恢复，旧 BOT_API_TOKEN 重新生成；旧会话、适配器令牌、主机许可、配对码失效，接入审批重新确认。

机器人保持暂停，旧总结计划停用、待发消息及待清理操作取消，未完成 Persona/讨论分析/互动模型任务改为需重试状态，防止将来开启 worker 时意外重放或产生新费用。已发生的 API 账目不擅自退款或修改，需人工核对未完成账目。仅启动网页，不启动模型或发送 worker。任务历史、创建者、素材、已发布版本、群配置和账目保留。

## 后续方案与发布顺序

1. 继续用新空目录安装和演练；先根据实际目标设备补做平台验收，不把源码可构建推断为所有设备已兼容。
2. 若后续获准替换线上，先核对发布差异、目标镜像/架构、域名/TLS、OAuth 回调、备份计划与机器人重新接入方案；备份后的新消息和配置不能丢弃。
3. 再取得最终一致性备份，在隔离目标恢复并核对表、文件、密钥、用户权限、任务状态和运行端身份；保留原实例与明确回退入口。
4. 正式发布严格按指定规范执行：开发侧 `oc-push`；获准进入生产发布阶段后，桥接侧通过 `oc-prod-release` 创建发布分支并评审 PR。开发提交、生产仓库发布和实际容器切换是不同步骤，不自动相互替代。
5. 仅在明确安排的切换窗口调整生产入口与运行端连接；先核对登录和原账号身份，再逐个启用机器人/后台任务。生产验证不应擅自向真实群发送测试消息。

当前没有执行上述生产切换步骤。指定流程见 [开发与生产发布脚本说明](https://github.com/oc-workspace/openclaw-workspace/blob/main/openclaw-开发与生产发布脚本说明.md)，服务器副本位于 `rococo-oc-workplace:/work/oc-projects/openclaw-workspace/openclaw-开发与生产发布脚本说明.md`。
