# 按群配置连续回复与跟进

后台「群管理 → 选择群 → 连续回复与跟进」提供：

- 是否限制未点名连续回复；默认开启。
- 每段连续回复上限：1–20轮，默认2轮。
- 轮数重置间隔：30–1800秒，默认180秒，从机器人最后一次成功回复起计算。
- 免点名跟进窗口：30–1800秒，默认180秒，仅同一群里已获回复的同一成员有效。

明确点名不受连续轮数拦截，成功回复后重新从第1轮计数；之后的免点名跟进和主动插话累计到这一段。达到上限的消息不会先排队等重置再补答。关闭轮数限制只取消这一项门控，全局总量、成员间隔、点名模式、话题范围、预算、时效、并发和发送去重仍然生效。玩笑识别与接梗开关不控制这些执行参数。

后端校验数据并保存到本群policy.conversation.reply_limits；013迁移只为缺少新字段的群补上原值2/180/180，保留其他配置，增加群revision并清除旧确认。runtime配置附reply_limits_contract_version=1，适配器只有真实应用后才能附reply_limits_version=1确认；仅旧conversation_policy_version=1不代表已应用新限额。后台等待“机器人已确认”，不能仅凭保存提示认为已经生效。

MaiBot原生admission、跟进识别、上下文轮数及成功发送后的计数重置都读取同一个reply_limits.for_group。未升级的旧后端和未托管群保留原全局行为；配置包含新字段但缺少正确契约时拒绝，不静默忽略。两个群可分别设置不同轮数与时间。

安装使用install-policy.py对policy.py的精确基线做幂等补丁，与上级banter.py、groupdesk_runtime.py、reply_limits.py同批发布。保留私有policy.json、模型配置与额度台账。deploy-native.py先做摘要与活动任务检查，再只重建MaiBot和bridge两个Docker容器；WeChat不重启。原生先升级以兼容旧后端，再发布后台；最后核对两群新revision均被确认。失败回滚仍恢复原收发开关。

自动化验证使用合成消息、独立SQLite/PostgreSQL、固定镜像断网运行；不向真实群发送测试。操作者授权的单条补答须另行核验来源、权限、当前Persona、配额、去重和verified回执。
