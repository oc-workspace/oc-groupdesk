# 慢模型等待与超过两分钟的回复致歉

针对模型耗时不定、上游或网络排队，允许点名请求等待较久，并在实际发送前按真实等待时间处理体验。没有单独的两分钟催等公告，也不增加一次模型请求。

## 生效参数

| 层级 | 参数 | 行为 |
| --- | --- | --- |
| MaiBot Planner | hard_timeout=300秒 | 每次规划最多等待5分钟；仍受整个任务截止时间限制 |
| 提供商HTTP | timeout=310秒 | 原生TOML与GroupDesk请求内私有路由同时修改 |
| 点名/连续跟进 | direct_turn_ttl_seconds=420秒 | 从首次采集时间开始计时，排队与处理共用7分钟，不是各7分钟 |
| 等待致歉 | wait_apology_seconds=120秒 | 发送前检查；恰好120秒仍正常，超过才加致歉 |
| Replyer | hard_timeout=60秒 | 保留；正常一次Planner后还留有回复生成和发送时间 |
| 普通主动插话 | 原有90秒排队/活动时效 | 保留，不让旧话题长期堵塞 |
| 初次入站来源时效 | 90秒 | 仍拒绝旧历史伪装成新请求；已正常入队的点名可等到420秒绝对截止 |
| 并发与配额 | 仍为1个模型调用/活动任务、5个排队请求 | 保留现有每日预算、频率、版本和语言门控 |

重试、多次模型调用共用同一个任务截止时间，为发送预留约5秒。若排队已用掉一部分7分钟，实际模型可用时间会相应减少，不保证每个排队请求都能重新获得完整5分钟。长等待会让其他消息排队；这次没有增加并发、改换模型或新增备用Key。

## 两分钟体验规则

时间从适配器的首次采集时间起算，包含排队、合并等待和模型调用；不使用微信UI可能共享的分隔标签冒充每条精确发送时间。同一人的补充或“还在吗”不重置计时。

- 120秒以内：发送层保留正文原样。
- 超过120秒：致歉放在同一条回复的正文之前，不拆成额外消息，不多占一次群发言配额。
- Planner在既有reply工具的wait_apology字段准备一句同语言、符合当前Persona的致歉，发送层只在超过阈值时使用；低于阈值会忽略。这是在原请求内准备的文字，不调用额外模型。
- GT合成语气示例：“抱歉久等，刚才这句话绕了点远路。[呲牙]”；英文：“Sorry for the wait. My answer took the scenic route. 😄”。示例不是GT历史原话；正常输出继续使用本群实际绑定的Persona Skill。
- 未提供字段时使用中、英、日等常用语言的短句兜底；继续执行本群语言检查。已经有道歉的补答不重复加。
- 致歉计入原单条字数上限；语言、版本、时效、预算、重复发送保护仍会检查。
- 超时最终没有生成正文时，不会只发道歉假装已完成回答；本功能不是失败通知或自动补答策略。

计时判定发生在提交微信发送前；发送后的客户端交付耗时另由既有delivery状态验证，无法提前保证手机实际显示时刻。latency_deliveries记录来源时间、提交时间、耗时、是否使用致歉及致歉哈希，不保存额外回复正文。

## 代码与安装

latency.py与既有policy.py同目录；install-latency.py对已安装恢复钩子的生产基线生成幂等变更：policy、group_guard、model_routing、bridge与原生reply工具。输入目录布局为limits/、bridge/、core/reply.py；先复制生产源码到隔离目录再执行，不直接以生产目录试错。

configure-timeouts.py只在服务器处理私有model_config.toml，保留注释，并逐字段验证除Planner超时与提供商timeout外所有字段完全一致。凭据不传出服务器、不提交Git。准备完毕并通过隔离测试后，备份原配置与SQLite，等待无活动任务，暂停收发，部署并只重建MaiBot和桥接；微信容器与登录保持。

received_at与wait_apology为增量字段，既有记录用原created/first回填；新请求使用真实首次采集时间。延长模型并发占用判断：3分钟以上仍活跃的请求不会被误认为释放了模型位置。保留原180秒孤立保留窗口及剩余任务截止时间，避免并发漏算。

回退使用本次服务器install-artifacts备份中的源码和TOML，保留账本及新字段，不删除聊天或重置预算。已有后台每小时巡检遵守活动任务的真实截止时间，不中断长请求进行恢复操作。

## 验证

使用可控时钟覆盖119.99/120/120.01秒、7分钟绝对截止、排队计时、不被催促续期、超过3分钟的并发占用、来源时效、普通插话过期、语言、字数与去重。原生镜像中用假传输验证实际Bridge.outgoing只提交一条消息、两分钟内无致歉、超时加同语言前缀、重复不发送；验证原生reply字段与300秒后Replyer仍能获得许可。断网环境运行，不向Shanghai Entrepreneurs Meetup或其他真实群发送测试消息。
