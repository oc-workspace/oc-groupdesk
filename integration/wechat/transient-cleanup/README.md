# 头像资料卡残留与辅助界面恢复

2026-11-01 23:05点名已采集正文，但临时层安全锁阻断昵称读取，未进入模型。手动关闭后新消息恢复；原点名仍缺昵称，不能伪装成刚收到的新消息。补答另遇到旧辅助根节点找不到搜索框，失败发生在正文输入前。

本补丁只改变SDK辅助窗口、昵称读任务和稳定到达行的方向更新，不取消未知窗口锁，也不自动重试发送。

- 普通昵称已可读时，不为了组织字段再开头像资料卡。
- SDK点击头像前记录干净窗口集合，只记录此后本次头像动作产生、符合资料卡特征或受限空白filler形状的顶层。恢复还需30秒内、同一主窗口和群、已记录的同一顶层、活动窗口属于微信且不是modal/dialog；最多额外Escape一次。原失败客户端仍锁定并丢弃，不能直接继续写入，也不重放已失败发送。
- 旧辅助根丢失搜索控件时，输入前只重新连接读取一次，重验群和窗口；仍无控件则失败，不通过坐标盲点或重试发送。
- 昵称读取失败按2/8秒退避，单条最多3次，状态最多512条；复用原到达ID与首次采集时间，不把补识别当新消息。
- 对同一arrival/appearance记录，后续UNKNOWN不能抹去此前已确认的incoming/outgoing；不把原本UNKNOWN推成incoming，已发回显仍不会进入入站。
- 暴露持续的ui_input_blocked状态，避免瞬时wechat_connected=true掩盖输入锁。现有每小时巡检识别它为degraded/ui_window_blocked，不反复重启微信，沿用Server酱独立微信告警、同故障去重和每日限额。未知窗口仍由管理员处理；没有增加30秒巡检。

`baseline.json`和`candidate.json`约束精确源码摘要，`install.py`在内存中验证全部候选再写入。重复安装字节一致，未知基线在改动任何文件前拒绝。`transient_recovery.py`与`test_transient_recovery.py`由安装器一并放入SDK。

验证：14项针对性用例纳入172项完整固定微信镜像断网测试，另17项巡检用例通过；无跳过、无真实群测试消息。单条用户授权补答与上述测试分开，发送须保留来源、当前Persona、配额和去重关系；失败或不确定不盲目重放。

发布仍走开发提交、生产PR核对合并。用此目录Dockerfile，以既有frame-identities镜像为基底构建带发布SHA标签的新镜像，比较镜像、候选及运行源码摘要。`deploy-root2.py --stage SDK候选目录 --manifest 验证清单 --release 生产SHA --monitor integration/maibot/availability/monitor.py`先核对活动任务和SDK空闲、备份三份SQLite及配置，仅停止/启动custom-svc-bowxt并复制同码；微信、MaiBot、桥接不重启。更新未来重建镜像和原build脚本末端钩子，保留此前frame-identity安装步骤。失败回滚源码、监控、私有环境和原开关，微信PID/StartedAt必须保持。

未知、非SDK产生、超龄、跨群或失焦的窗口不自动清理；不能保证微信永久在线或UI永不变化。方案让可证明的窗口故障可以自愈，无法确认的错误可见并按现有小时巡检告警。
