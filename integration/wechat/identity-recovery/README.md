# 群消息方向、昵称与补读队列

Linux 微信的辅助功能树有时只有正文，没有发送者和可靠的收发标记。正文已入库不等于已满足入站条件；桥接仍须确认 incoming、群和发送者，避免自己的回显或系统消息触发回复。

本补丁接续 frame-identity 与 transient-cleanup，不取消方向和昵称校验：

- 原有方向判定不明确时，额外核对完整头像槽。只有虚拟行与消息面板的边界一致、两个头像区域都在当前可见范围、单侧存在明确像素证据时，才确认方向。头像裁切、气泡局部行、双侧有内容或证据不足仍保留 unknown。
- 未知方向的文字消息也可以排入有限的只读重采集；没有 独立确认的 incoming 时不点击头像。每阶段最多3次，沿用2/8秒退避；方向得到新证据后可进入一次新的昵称补读阶段。
- SQLite identity_resolution 仅记录seq、群、消息ID、阶段、次数、状态和原因，不复制正文、头像或昵称。最多512条，预算跨进程重启保留。后台状态显示pending/unresolved/resolved计数。
- 已耗尽预算的旧条目在选择backlog时即跳过，不再阻塞后续成员。修复成功沿用原消息ID、seq和observed_at，不把昵称更新当作新消息，不刷新时效、不重放已发送回复。
- 每小时巡检发现有限重试耗尽，使用原独立微信告警及去重机制提示采集不完整，不反复重启微信；巡检频率仍为每小时。

`install.py`在内存中验证全部基线、补丁与新模块摘要，随后才写入；未知基线拒绝，重复安装字节一致。既有构建脚本在frame-identity与transient-cleanup之后加入本安装器。Docker镜像绑定经核对的生产发布SHA。

部署使用同目录`deploy-root2.py`，校验测试清单和源码摘要、备份SQLite/配置、等待任务空闲，仅重启custom-svc-bowxt；微信进程、微信容器、MaiBot和桥接不重启。自动回滚后即便微信未能重连，也会恢复原有桥接开关。无法确认的界面仍需检查，不能保证每条消息都能恢复姓名。

验证以固定微信镜像、断网和合成消息进行，完整SDK184项、巡检20项。测试不向任何真实群发消息。真实补答属于用户单独授权的运维发送，必须有来源证据、权限/语言/配额/去重检查及verified回执，不能当作自动链路测试通过。
